# EMF Weekly Report

## Reporting Period

August 8–14, 2026

The final documentation checkpoint occurred just after midnight UTC on
August 15 and is included because it completed the August 14 work session.

## Executive Summary

EMF advanced from mature workflow and evidence foundations into a
substantial Veterans Claims Domain Extension and a working,
provider-neutral Evidence Intelligence Services Layer.

The week produced 333 commits dated August 8–14. The final solution
contains 19 .NET 10 projects, and the full automated suite reports
437 passing tests plus one intentionally skipped live Azure integration
test.

## Platform Progress

- Strengthened workflow recovery, resume, restart, retry, checkpoint,
  and execution-coordination boundaries.
- Continued evidence, artifact, provenance, relationship, integrity,
  and atomic-persistence development.
- Added versioned provider-owned SQLite migration infrastructure,
  including security-audit schema migration.
- Added protected artifact content, envelope encryption, key
  rewrapping, authorization, and security-audit capabilities.
- Migrated all projects from .NET 8 to .NET 10.
- Upgraded SQLite dependencies and cleared the detected high-severity
  transitive vulnerability.
- Added a useful root README and Azure OpenAI operations guide.

## Veterans Claims Domain Extension

- Established the platform-versus-domain boundary in ADR-012.
- Defined the Veterans Claims domain boundary in ADR-013.
- Added identities and models for Veterans, Claims, Claim Issues,
  Submissions, Conditions, Service Connection, Service Events,
  Exposures, Regulatory Knowledge, Evidence Development, Findings,
  Decisions, Ratings, and Evidence Packages.
- Preserved Claim Issue as the primary longitudinal adjudication unit.
- Linked domain records to platform artifacts instead of creating
  separate evidence or provenance systems.
- Added provider-neutral persistence contracts and SQLite adapters.
- Added longitudinal history, staged evaluations, regulatory
  repositories, and forward/reverse relationship queries.
- Implemented service-connection basis relationships for claimed,
  service-connected, and preexisting conditions, service events,
  exposures, and presumptions.

## EISL and Intelligence Progress

- Accepted ADR-026 for provider-neutral capabilities, agents, routing,
  protection, traceability, cancellation, and review-gated promotion.
- Added deterministic Development providers for segmentation,
  summarization, and keyword extraction.
- Added short- and long-text intelligence agents and coordination.
- Added fail-closed routing and capability execution with audit records.
- Added explicit promotion of reviewed intelligence output to Evidence.
- Added console analysis, summarization, and promotion commands.
- Accepted ADR-027 selecting Azure OpenAI as the first production
  intelligence provider.
- Added the Azure OpenAI adapter, managed-identity client factory,
  normalized metadata, failure classification, production composition,
  and console summarization.
- Added an opt-in live Azure integration test that remains skipped in
  ordinary test runs.
- Verified that prompts and generated responses are absent from audit
  facts.

## Security Progress

- Added the Azure Key Vault adapter and envelope-encryption services.
- Added key-reference, cryptography-factory, and rewrapping boundaries.
- Preserved Microsoft Entra ID and managed identity as the production
  authentication mechanism; no Azure OpenAI API keys were introduced.
- Enabled the EMF development VM system-assigned managed identity.
- Verified VM managed-identity authentication.
- Verified acquisition of a Cognitive Services bearer token.
- Restricted the planned Azure OpenAI resource to the existing EMF
  virtual network and subnet design.

## Verification

- Full suite: 437 passed, 0 failed, 1 intentionally skipped.
- The skipped test is categorized as Azure integration and cannot call
  Azure without explicit activation and configuration.
- Build completed without warnings after migration cleanup.
- NuGet vulnerability audit reported no known vulnerable packages.
- Git branch remained synchronized with `origin/main`.

## Key Decisions

- Platform owns process and evidence semantics; Domain Extensions
  provide expertise; EISL provides intelligence capabilities.
- Protected information may reach a provider only through explicit
  capability, provider, and classification authorization.
- Intelligence output is not Evidence until separately reviewed and
  promoted.
- Development intelligence is deterministic verification behavior,
  not a production fallback.
- Azure OpenAI production authentication uses managed identity and
  least-privilege RBAC.
- Provider SDK types and transport details remain inside adapters.

## Blockers

- The Azure OpenAI resource has not yet been created.
- No model deployment or Azure OpenAI endpoint exists yet.
- The VM identity still requires a resource-scoped
  `Cognitive Services OpenAI User` role after resource creation.
- The live integration test cannot run until those items exist.

## Risks

- Azure credits show $184.96 remaining and expire September 1, 2026.
- Model inference introduces variable cost, latency, throttling, and
  regional capacity constraints.
- Protected evidence must not be used during initial connectivity
  testing.
- Microsoft is moving Foundry integrations toward the OpenAI v1 API;
  the current adapter should be reviewed separately for a controlled
  SDK migration rather than changed during cloud provisioning.
- The unusually high delivery pace makes disciplined checkpoints,
  review, and rest important.
